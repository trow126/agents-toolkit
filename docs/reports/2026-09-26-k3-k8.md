# K3 と K8 の確認（2026-09-26）

指示書の付録 D の K3 と K8 を、integration 環境（host mini、Claude Code 2.1.282）で確かめた。どちらも owner の指示で行った（P8-Q6）。

## K3: managed の deny `Agent(codex:codex-rescue)` は bypass の下で効くか

- 構成: 候補の managed（hash `39a2490925354d094b55fe95dda7dc9ef74bb29639e1137b0c25ec0e63483d38`、`permissions.defaultMode: bypassPermissions`）、`bootstrap.sh --apply`、codex-plugin-cc 1.0.6。
- 手順: `claude -p` に、`Agent` tool を `subagent_type: "codex:codex-rescue"` で1回だけ呼ばせた（model は opus、1回あたり `--max-budget-usd 0.25`）。
  - A（対照）: managed の PreToolUse hook（`claude/hooks/pre-bash-validate-hook.sh`、matcher `Agent`）がある状態。
  - B: mini の clone の中だけで、hook の codex-rescue を拒否する分岐を無効にした状態（実行後に戻した。commit はしていない）。
- 結果:
  - A: hook が拒否した（`PreToolUse:Agent hook error: ... Blocked: codex:codex-rescue Agent 経由の委任を拒否した。...`）。
  - B: permission rule が拒否した（`Agent type 'codex:codex-rescue' has been denied by permission rule 'Agent(codex:codex-rescue)' from policySettings.`）。
- 結論: bypassPermissions の下でも、managed の deny だけで呼び出しは拒否される。Phase 4 で確認した「deny を置くと、その type が Agent tool の説明から消える」とあわせて、K3 は解消した。hook は、拒否の理由と代わりの手順（`codex-delegate`）を示すために残す。
- 費用: Claude 約 0.15 USD（A 0.13、B 0.02）。

## K8: `claude plugin eval` でこの機械の skill の起動精度を測れるか

- 使える。2.1.282 の `claude plugin eval` は、`.claude-plugin/plugin.json` と `skills/` を置いた directory を plugin として評価できる。既定では HTML の報告を claude.ai に公開するので、必ず `--no-publish` を付ける。
- suite は `scripts/build-skill-trigger-eval.py` が組み立てる。
  - manifest が Claude に配布する skill のうち、モデルが自分の判断で起動できる10個（article-style、branch-cleanup、gh-codex-drive、gh-finish、gh-issue、gh-start、git-operations、implementation-quality、issue-writing、model-routing）を、一時的な plugin `atk` に copy する。
  - manual-only と、live の `skillOverrides` が user-invocable-only の skill（gh-pr、gh-review、config-audit、gh-index、python-refactor-analysis）は、live でモデルに一覧されないので除く。
  - case は12件。紛らわしい組（§6.5）ごとに、期待する skill の起動と、隣の skill が起動しないことを `tool_used` の grader で判定する。D3①（明示の無い実装依頼で gh-codex-drive が起動しない）も含む。
- 実行: `claude plugin eval <suite> --runs 3 -j 2 --model opus --ablation none --no-publish --max-cost-usd 3.9 --trust-plugin`（mini には managed の env pin が無く、`opus` は CLI の既定の解決先）。
- 結果: 12件を3回ずつ、36回すべてで期待どおりの skill が起動し、判定した隣の skill は一度も起動しなかった。

| case | 期待 | 起動しないことを判定 | 結果 |
|---|---|---|---|
| article-style | article-style | — | 3/3 |
| branch-cleanup | branch-cleanup | git-operations | 3/3 |
| implementation-quality | implementation-quality | gh-start | 3/3 |
| git-operations | git-operations | gh-finish、gh-start | 3/3 |
| gh-start | gh-start | gh-codex-drive | 3/3 |
| gh-codex-drive | gh-codex-drive | gh-start | 3/3 |
| no-implicit-codex | — | gh-codex-drive | 3/3 |
| gh-finish | gh-finish | git-operations | 3/3 |
| gh-issue-close | gh-issue | issue-writing | 3/3 |
| gh-issue-create | gh-issue | — | 3/3 |
| issue-writing | issue-writing | gh-issue | 3/3 |
| model-routing | model-routing | — | 3/3 |

- 費用: Claude 約 2.53 USD（1件の試行 0.05 を含む。上限は owner が 4 USD に設定）。
- 制約: 各 run の trace は実行後に消える一時 directory にあった（`--keep-temp` を付けなかった）ので、起動した skill は grader の判定（「Skill called 1x」など）で確かめた。plugin として読み込ませたので、skill 名は `atk:<name>` になり、live の user skill とは読み込み方が異なる。
- 再測定: skill の description、Claude Code の version、`skillOverrides` が変わったときに、`docs/runbooks/integration-environment.md` の手順で同じ suite を実行する（§12 の Level 2 のきっかけ）。
