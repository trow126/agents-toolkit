## K2: 2026-09-04 に gpt-6-astra へ切り替わった経路

**結論（推定。確度は高い）**: 自動の無断移行ではない。0.153.3 の TUI を最初に起動したときに、`config.toml` の `model` / `model_reasoning_effort` が書き換えられた。TUI の model availability の案内か、`/model` で選択され、Codex がそれを保存したと考えられる。

根拠:

- 2026-07-10 の `config.toml` の backup には、`model = "gpt-5.6-sol"`、`model_reasoning_effort = "ultra"` が明示されていた。現在は `gpt-6-astra` / `medium` になっている。
- state DB では、0.151.0 の最後の session が 2026-09-03 05:28 UTC（gpt-5.6-sol/high）、0.153.3 の最初の session が 2026-09-04 20:02 UTC（codex-tui）。この session は、最初の turn から gpt-6-astra/medium だった。
- `config.toml` の `[tui.model_availability_nux]` に `gpt-6-astra = 3` が記録されている。TUI が新しいモデルの案内を3回表示した記録である。
- 公式の releases: 0.153.1 で「既定の model を変えずに API で Astra を設定できる」ようになり、0.153.3（2026-09-04）で model picker に追加、0.153.4 で「model を明示していないときの bundled の既定」になった。`model` を明示している config を自動で書き換えるという記述は無い。
- `logs_2.sqlite` は 2026-09-20 以降しか残っておらず、書き換えの瞬間の log は無い。

影響と対策:

- TUI の案内や `/model` は、routing の昇格ゲートを通らずに `config.toml` の既定を変えられる。
- Phase 1 で、委任は常に `codex-route.env` の `--model` / `--effort` を渡すようにした。そのため、委任で使うモデルは `config.toml` から切り離されている。
- discovery は `config.toml` の model / effort の変化を WARN として報告する（Level 1 の候補）。

## K14: built-in plugin `agents-md` の有効 / 無効が保存される場所

**結論**: settings の `enabledPlugins["agents-md@builtin"]` に保存される。キーが無ければ有効（既定）。`/plugin` で無効にすると false が書かれ、AGENTS.md の読込が使えなくなる。

根拠:

- Claude Code 2.1.282 の binary の built-in plugin の解決処理は、`enabledPlugins["<name>@builtin"]` を読み、値が無ければ `defaultEnabled`（未指定なら true）を使う。
- 公式の memory の docs に「`/plugin` で built-in `agents-md` plugin を無効にすると AGENTS.md support が使えない」とある。mode は `pluginConfigs["agents-md@builtin"].options.instructionFiles` で指定し、値は `claude-md` / `claude-md-or-agents-md`（既定）/ `claude-md-and-agents-md` / `managed-only` の4つ。
- discovery は user と managed の `enabledPlugins["agents-md@builtin"]` を読み、false なら WARN を出す。
