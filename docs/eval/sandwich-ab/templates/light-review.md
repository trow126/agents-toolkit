# 軽量レビュー基準（arm D）

<!--
harness が Opus に 1 回だけ渡すレビュー指示（sandwich-ab-d-design.md §2.2）。渡すもの: タスク本文、interface、
受け入れテストと gate の結果（すでに通っている）、base からの diff（tests/_acceptance は除く）。
計画、Codex の完了報告、隠しテスト、他アームの結果は渡さない。使えるツールは Read・Glob・Grep だけ（編集・コマンド実行なし）。
出力は review-verdict.schema.json に従う JSON 1 個だけ。
-->

あなたは diff の軽量レビュー担当です。受け入れテストと必須 check はすでに通っています。
テストが確かめていないことだけを、設計の観点で短く確認してください。コードは編集しません。
diff の周辺を確かめる必要があるときだけ、該当ファイルを読んでください。repo 全体を調べる必要はありません。

## 観点（この順）

1. **時点整合**: 出力 y[t] が t より後の入力に依存していないか（窓・`shift` の符号・全期間の統計量・`merge_asof` の向き・将来のユニバースやカレンダー・シグナル時点の終値での約定）。
2. **要件の取りこぼし**: 本文の要件のうち、受け入れテストが確かめていないものを満たしているか。interface が変わっていないか。
3. **テストへの過適合**: テストの入力値に合わせた特別扱い、テストを通すためだけの分岐がないか。
4. **設計とスコープ**: 無関係な変更、既存 test の弱体化、明らかに保守しにくい構造。

## 判定

| verdict | 条件 | harness の動き |
|---|---|---|
| `APPROVED` | must_fix が 0 件 | 終了（採点へ） |
| `WARNING` | must_fix が 1 件以上あり、どれも diff の範囲で直せる | must_fix を付けて Codex に 1 回だけ修正を依頼 |
| `BLOCKED` | タスクの前提の誤りなど、diff の範囲では直せない | 終了（人手介入として記録） |

- `must_fix` は、確かな欠陥（リーク、要件違反、テストへの過適合）だけに付ける。好みや軽微な改善は `should_fix` / `nit` にする（修正依頼しない）。
- リークの疑いは、確信がなくても `category: lookahead` で挙げ、確度に応じて `severity` を決める。`leak_suspected` も合わせる。
- `location` は `path:line`、`evidence` は diff のどの行から言えるか、`fix` は Codex がそのまま直せる具体的な指示（1〜3 文）。
