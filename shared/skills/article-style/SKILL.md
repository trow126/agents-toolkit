# article-style — 公開文章から AI 臭を消す

参考: https://zenn.dev/coji/articles/natural-japanese-ai-smell-lint
（owner の明示依頼がない限り変更しない）

公開向けの文章を書く・直すときは、初稿を書く前にこの規則を読む。下のチェックリストでの自己検査は、
公開向けの文章 file を「変更した」と報告する前と、その file を含む commit・push の前に行う。
同じ session でその file を後から編集したら、変更した箇所をもう一度検査する。対象: 記事、外部向け README、outreach 文面、リリースノート等。コード内コメントや
内部設計文書は対象外。

## 書き方の規則

### リズム

- 文長は内容に合わせ、均一にしない。等長の文が 3 つ以上並んだら書き直す
- 段落の文数も不揃いにする。「全段落きっかり 3〜4 文」は機械的すぎる
- 体言止めを適度に混ぜる（1 記事に数回）。「〜です。〜ます。」だけで通さない
- 「以上。」「結果は KILL。」のような一語・一句の文を効果的に使う

### 構文の癖を消す

- 「〜ではなく〜」の否定→肯定対比は 1 記事 1〜2 回まで。人間の比率は 1.5% 程度、
  AI は 8% 使う
- 「重要なのは」「つまり」「まさに」「〜と言えるでしょう」「〜ではないでしょうか」等の
  定型の接続・締めを避ける
- 対句・三連の並列（「安く、速く、正確に」型）を決め台詞として乱発しない
- 英語では: em-dash の連発、"does not survive contact with"、"the X is Y, not Z" 対比、
  "Here's the thing" 系の定型フックを避ける

### 語彙

- 造語・ブランド語を本文で乱発しない。固有名は初出 1 回で十分。以後は一般語で言い換える
  （例: 「Public Kill Ledger」→「検証の台帳」「このリポジトリ」）
- 比喩は 1 記事 1 個まで。「測定器」「羅針盤」「設計図」のような気取ったメタファーの
  積み重ねはよくある癖
- カタカナ語の連続を避け、日本語で言える語は日本語で書く

### 構成

- 箇条書き・表は本当に列挙が必要な場所だけ。手順や理由は地の文で書けるなら地の文で
- 見出しを整いすぎた並列（全部体言・全部同じ文字数）にしない
- 「はじめに / まとめ」の定型サンドイッチを避け、書き出しは具体的な場面や事実から入る
- 絵文字・強調（**太字**）の乱用をしない。太字は 1 記事 2〜3 箇所まで

### 内容

- 誇張しない。数値・事実は一次情報のとおり。保証表現・断定の水増しをしない
- 一人称の判断・感想を適度に入れる（「〜と踏んでいました」「正直、意外だった」）。
  無人称の解説文だけで構成しない

## 公開前チェックリスト

- [ ] 等長の文が 3 連続している箇所がない（日本語のみ）
- [ ] 否定→肯定の対比が 2 回以下（日本語は「〜ではなく〜」、英語は "the X is Y, not Z" を数える）
- [ ] 体言止めまたは一句文が 1 回以上ある（日本語のみ）
- [ ] 「構文の癖を消す」の定型が残っていない（日本語は定型の接続・締め、英語は定型フック）
- [ ] 比喩が 1 個以下
- [ ] 造語・固有名は初出以後に一般語で言い換えてある
- [ ] 箇条書きにした箇所は本当に列挙が必要か再確認した
- [ ] 本文の数値ごとに、出典の該当箇所と、どの実験・指標・版・日付の値かを 1 行ずつ書き出し、本文の主張と同じ対象の値であることを突合した。出典には、この session の command 出力・log・test 結果も含む（command と実行回を書く）。記録のない数値は本文に残さず、未確認として owner に示す
- [ ] 音読して息継ぎのリズムが不自然でない
