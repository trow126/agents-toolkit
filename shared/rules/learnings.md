## 汎用学習事項（Learnings）

言語非依存・プロジェクト非依存の教訓。言語固有の品質ゲートは共有正本 `python-guidelines.md` 等に定義する。

### CLI操作の注意点

- **jqスライス括弧順序**: `(.body[:400])` の閉じ括弧は内側から `]` → `)` → `}` → `]`。誤: `(.body[:400)}]`、正: `(.body[:400])}]`
- **`pkill -f` / `pgrep -f` は自分を実行中のshellにも一致する**: パターン文字列を含む `bash -c` 自体が一致し、`pkill` は自分を kill し（exit 144）、`while pgrep -f` の待機ループは終わらない。先頭文字を括弧で囲み `pkill -f "[k]aizen_keiba.loop"` とする。Claude Code では `pre-bash-validate-hook` が括弧なしを block する (理由: 4 session で再発し、2026-10 に待機ループが 4.5 時間止まった)
- **終了待ちはポーリングより完了通知を使い、短い確認コマンドも `timeout` で包む**: 出力を書き終えたプロセスが終了処理で止まることがあり、待つ側は完了を検知できない (理由: 2026-10 に 12.5 時間気づかなかった)
- **待機ループは判定コマンドを起動前に1回単独で実行し、失敗でも抜けるように書く**: ループ内の失敗（構文エラー・例外・API 応答の変化）ではループが終わらず、`2>/dev/null` や `|| echo` で「まだ」と同じに見える。stderr を残しても通知には出ない。連続失敗で `exit 1` し、待機対象の終了も終了条件に入れる。Claude Code では `pre-bash-validate-hook` が `while` / `until` を含むコマンドの `python -c` の構文エラーを block する (理由: 2026-11 に完了から約1時間気づかなかった)

### エージェント設定の注意点

- **共有ルールは原則ベースに保つ**: 細則を列挙せず、モデルの判断に任せる。共有正本は Codex も消費するため、Codex 側で遵守低下を観測したら Codex 専用の補足を `codex/` 側に足す（正本を再肥大化させない）

### 実行環境の注意点

- **systemd user service の PATH は最小構成**: 外部 CLI（claude/codex 等）は絶対パスを設定で明示し、検証は `systemctl --user show-environment` の PATH を再現して行う (理由: シェルでの成功は偽陰性になる。複数プロジェクトで独立に再発)
